# Governed experiment reference results

These files are the minimal authoritative numerical inputs used to regenerate
the current paper tables and figures. They are `REFERENCE_BENCHMARK_DATA`, not
VAMOS RunManifest or StudyManifest directories. Raw runs, traces, tuning
databases, backups, derived statistics, plots and LaTeX remain external or
ignored.

The frozen source commit for this retained set is
`55e1b52de82d6bb9e0f2b43c7847925404607085`. Repeating optimization campaigns
is publication-scale work and is not part of routine CI. Reanalysis of the
retained CSVs requires no new optimization runs.

`tuned_nsgaii_resolved.json` is a `SCIENTIFIC_SOURCE_INPUT`: the fully resolved
configuration selected by the archived tuning campaign. Its budget is 16 KiB;
raw studies and histories are not retained in the product tree.

Any new reference result must add its exact path, generation command, source
commit, schema, expected use and size budget here before it is tracked.

## Reading the data

Start with the [paper reviewer guide](../paper/README.md) for installation,
read-only inspection, a small optimization example and isolated analysis rebuilds.
The following links open the actual retained inputs; no optimization is required
to inspect them.

| [SMS-EMOA](benchmark_paper_smsemoa.csv), [MOEA/D](benchmark_paper_moead.csv) | Additional algorithm comparisons and supplementary statistics |
| [Steady-state NSGA-II](benchmark_paper_nsgaii_ss.csv), [external archive](benchmark_paper_nsgaii_archive.csv) | Variant runtime comparisons |

The main benchmark CSVs contain one observation per
`(algorithm, framework, problem, n_evals, seed)`. Include `n_obj` and `n_var` in
the key for ZCAT scalability; include experiment, population size, engine and
timing policy for scaling. Convergence observations also distinguish evaluation
checkpoints. Framework coverage varies by algorithm and problem family; do not
assume that every file contains a complete cross-product of all frameworks.

| Column | Meaning |
|---|---|
| `algorithm`, `framework`, `problem` | Recorded implementation and benchmark identifiers |
| `seed` | Random seed; primary comparisons use 0 through 29 |
| `n_evals` | Evaluation budget, or cumulative checkpoint for convergence; primary comparisons use 50,000 |
| `runtime_seconds` | Recorded elapsed runtime in seconds; compare within a common experimental condition |
| `n_solutions` | Number of returned solutions; external archives can exceed population size |
| `hypervolume` | Recorded normalized hypervolume; higher is better under the same reference/normalization policy |
| `igd_plus` | Recorded IGD+; lower is better under the same reference-front policy |
| `peak_memory_mb` | Recorded peak memory measurement in MB, as measured by the memory script |
| `n_obj`, `n_var`, `pop_size` | Objective count, decision-variable count and population size |
| `experiment`, `engine`, `timing_policy` | Scaling condition, numerical backend and available timing metadata |

The [manuscript protocol](../paper/manuscript/main.tex) describes timing and
quality metrics; [benchmark_utils.py](../paper/benchmark_utils.py) owns the paper
reference-front and hypervolume policy. Read CSVs directly for independent
analysis. Current `vamos.load_run`/`load_result` readers are for canonical run
directories, not these tables.

## Experimental field conventions and analysis scope

- Script `01_run_paper_benchmark.py` currently supports NSGA-II, its steady-state
  and external-archive variants, SMS-EMOA and MOEA/D. Its `all` setting selects
  only the two NSGA-II variants; use `VAMOS_PAPER_ALGORITHMS` with an explicit
  comma-separated list when planning a campaign. AGE-MOEA, NSGA-III and SPEA2
  measurements are retained inputs, without a current runner in that script.
- Script `31_run_zcat_all_tables.py` appends two-objective, 30-variable ZCAT
  observations to the per-algorithm benchmark CSVs. It does not recreate
  `benchmark_zcat_scalability.csv`, which contains a dimensionality sweep.
- `benchmark_paper_nsgaii_ss.csv` retains one extra observation for jMetalPy,
  ZCAT1, seed 0 with `n_evals=200`, alongside the 50,000-evaluation campaign.
  Keep budgets separate when aggregating; filter explicitly to `n_evals == 50000`
  for the publication-budget comparison. The reviewer summary preserves the
  200-evaluation observation as its own condition. The author variant-table
  updater currently aggregates all rows, so review that filter before using its
  output to replace submitted values.
- `scaling_vectorization.csv` records runtime for all 220 observations. Its 40
  objective-count observations cover DTLZ2 with 2, 3, 5 and 8 objectives, NumPy
  and Numba, and five seeds per combination. Their `hypervolume` cells are empty
  because [the scaling script](../paper/03_run_scaling_experiment.py) explicitly
  sets `hv_enabled=False` for this timing experiment. Hypervolume is outside
  the measurement scope of that sweep.
- In the same file, `timing_policy` is empty for all 95 NumPy observations.
  The script writes this label for Numba JIT warm-up conditions; it does not
  assign a JIT policy to NumPy. The empty cells therefore denote an inapplicable
  field, while `runtime_seconds` and `runtime_per_eval` contain the measurements.
- The reviewer summary counts the recorded numerical values for each metric
  and computes medians from those values only. A metric outside a condition's
  measurement scope has a count of zero and an empty median.
- The historical CSV format stores tabular measurements for statistical
  reanalysis. The current run-artifact format additionally stores population
  arrays, environment information and a resolved specification for supported
  exact replay. These are separate artifact formats with different purposes.
- The pinned publication environment documents the maintained analysis stack;
  it does not by itself identify the historical development executable or make
  current-machine timings equal to the submitted measurements.
